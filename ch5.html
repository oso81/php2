1.1 أولًا: تصميم مخطط ERD

First: Design your ER diagram based on your scenario

An ER diagram (Entity-Relationship Diagram) is a visual representation of the database structure, showing tables, their fields, and the relationships between them.

3. إنشاء ملف الاتصال بقاعدة البيانات (Database Connection)

Next step

Create a file of connection between your database and your PHP interfaces.

الترجمة: الخطوة التالية: أنشئ ملف اتصال بين قاعدة البيانات وواجهات PHP الخاصة بك.

Three ways of creating connection

  1. mysqli (procedural)
  2. mysqli (object-oriented)
  3. PDO — we will use only PDO

الترجمة: ثلاث طرق لإنشاء الاتصال:

  1. mysqli بالنمط الإجرائي.
  2. mysqli بالنمط الكائني التوجه.
  3. PDO — وهو ما سنستخدمه فقط في هذا المقرر.

3.1 الاتصال باستخدام mysqli

Example — MySQLi Object-Oriented

<?php
$servername = "localhost";
$username   = "username";
$password   = "password";

// Create connection
$conn = new mysqli($servername, $username, $password);

// Check connection
if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
}
echo "Connected successfully";
?>

الترجمة: هذا المثال يستخدم mysqli بالنمط الكائني التوجه. إذا فشل الاتصال، يتم عرض رسالة خطأ عبر die() وإيقاف التنفيذ.

3.2 الاتصال باستخدام PDO

Example — PDO

<?php
$servername = "localhost";
$username   = "username";
$password   = "password";

try {
    $conn = new PDO("mysql:host=$servername;dbname=myDB", $username, $password);

    // set the PDO error mode to exception
    $conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    echo "Connected successfully";
}
catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}
?>

الترجمة: يستخدم PDO كتلة try...catch لمعالجة الأخطاء. السطر setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION) يجعل PDO يرمي استثناءات عند حدوث أخطاء.

3.3 ملف conn.php النموذجي

What inside conn.php??

<!-- connect via pdo -->
<?php
try {
    $db = new PDO(
        'mysql:host=localhost;dbname=attend_mangement;charset=utf8',
        'root',
        ''
    );

    $db->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
    $db->setAttribute(PDO::ATTR_EMULATE_PREPARES, false);

    echo "good connection";
}
catch (Exception $e) {
    echo "connection filed";
}
?>

📌 شرح محتوى conn.php:

  • mysql:host=localhost: خادم MySQL على الجهاز المحلي.
  • dbname=attend_mangement: اسم قاعدة البيانات.
  • charset=utf8: ترميز الأحرف لدعم العربية.
  • 'root', '': اسم المستخدم (root) وكلمة المرور (فارغة).
  • ATTR_ERRMODE, ERRMODE_EXCEPTION: رمي استثناءات عند الأخطاء.
  • ATTR_EMULATE_PREPARES, false: استخدام Prepared Statements الحقيقية بدل المحاكاة.

الفرق بين PDO و MySQLi

وجه المقارنة PDO MySQLi
دعم قواعد البيانات ✅ 12 نظامًا مختلفًا (MySQL، PostgreSQL، SQLite، ...) ❌ MySQL فقط
النمط كائني التوجه فقط إجرائي + كائني التوجه
Prepared Statements ✅ مدعومة (مع تسميات مرنة) ✅ مدعومة
الاستخدام في المقرر ✅ نستخدمه للمقارنة فقط

📌 الفرق الجوهري:

PDO يعمل على 12 نظام قاعدة بيانات مختلف، بينما MySQLi يعمل فقط مع MySQL.

4. أنواع أوامر SQL والعمليات الأساسية (SQL Command Types & Operations)

4.1 أنواع أوامر SQL (SQL Command Types)

Review: SQL Command Types

  • Data Definition Language (DDL) — used to create and modify database objects.
  • Data Manipulation Language (DML) — used to insert, update, delete, and view the data in database objects.
  • Control Language (CL) — ???

الترجمة: مراجعة لأنواع أوامر SQL:

النوع الاسم الكامل الاستخدام أمثلة
DDL Data Definition Language إنشاء وتعديل كائنات قاعدة البيانات (جداول، قواعد بيانات، فهارس). CREATE, ALTER, DROP, TRUNCATE
DML Data Manipulation Language إدراج وتحديث وحذف وعرض البيانات داخل كائنات قاعدة البيانات. INSERT, UPDATE, DELETE, SELECT
CL Control Language التحكم في المعاملات والصلاحيات. COMMIT, ROLLBACK, GRANT, REVOKE

4.2 الإدراج (INSERT)

Original — Inserting a value for every field

INSERT INTO tablename VALUES(value1, value2, ...)
  • You must include a value for every field.
  • You must list the values in the correct order.
  • To find the correct order, look at the table in the Object Browser.
  • Why? The DBMS is expecting certain data types for each field. If the data types are not correct, an error occurs.

الترجمة: صيغة الإدراج:

  • يجب تضمين قيمة لكل حقل.
  • يجب سرد القيم بالترتيب الصحيح (نفس ترتيب الحقول في الجدول).
  • لمعرفة الترتيب الصحيح، انظر إلى الجدول في Object Browser.
  • لماذا؟ لأن DBMS يتوقع أنواع بيانات معينة لكل حقل، وإذا لم تكن الأنواع صحيحة يحدث خطأ.

Example — Inserting into candy_product

INSERT INTO candy_product
VALUES (6, 'Chocolate Covered Ants', 6.25, 7.50);

ملاحظة: يجب أن تكون القيم بنفس الترتيب الذي ظهرت به الحقول عند تعريف الجدول، وبنفس الأنواع (رقم، نص، رقم عشري...).

4.3 التحديث (UPDATE)

General syntax

UPDATE tablename
SET field1 = new_value, field2 = new_value, ...
WHERE search_condition(s);

الترجمة: الصيغة العامة:

  • UPDATE — اسم الجدول.
  • SET — تعيين القيم الجديدة للحقول.
  • WHERE — شرط تحديد السجلات التي سيتم تحديثها.

📌 ملاحظات على UPDATE:

  • يمكن تحديث السجلات في جدول واحد فقط في كل مرة.
  • يمكن تحديث عدة سجلات في نفس الجدول إذا طابقت جميعها شرط البحث.
  • ⚠️ خطير: إذا نسيت WHERE — سيتم تحديث جميع السجلات!

Examples — UPDATE

-- Update a single record
UPDATE candy_product
SET prod_desc = 'Chocolate Obsession', prod_price = 8.5
WHERE prod_id = 6;

-- Update multiple records matching a condition
UPDATE candy_product
SET prod_price = prod_price * 1.1
WHERE prod_price > 10;

4.4 الحذف (DELETE)

Syntax

DELETE FROM tablename WHERE search_condition;

-- Example
DELETE FROM candy_product WHERE prod_id = 6;

📌 ملاحظات على DELETE:

  • يحذف عدة سجلات إذا حدد شرط البحث عدة سجلات.
  • ⚠️ خطير جدًا: إذا حُذف شرط WHERE — سيتم حذف جميع السجلات في الجدول!
  • لا يمكن حذف سجل في الجدول الأب إذا كان مرجعًا كمفتاح أجنبي في جدول آخر (Referential Integrity).

5. الوصول إلى MySQL باستخدام PDO (Accessing MySQL Using PDO)

5.1 بنية التطبيق (Application Structure)

Application Structure

The web application interacts with the database through a well-defined structure: End User ↔ Application Software (PHP) ↔ Database Data Model; and separately: Developer ↔ Application; DBA ↔ Database Tools (phpMyAdmin) ↔ Database Data Model.

الترجمة: يتفاعل تطبيق الويب مع قاعدة البيانات من خلال بنية محددة:

1

End User

المستخدم النهائي يتفاعل مع التطبيق عبر المتصفح.

Browser
2

Application Software (PHP)

التطبيق يترجم طلبات المستخدم إلى استعلامات SQL.

PHP Code
3

Database Data Model

قاعدة البيانات تنفذ الاستعلام وتُرجع النتائج.

MySQL

📌 الأدوار في البنية:

  • Developer (المطور): يتعامل مع Application Software.
  • DBA (مدير قاعدة البيانات): يتعامل مع Database Tools (phpMyAdmin) لإدارة Database Data Model.

5.2 إنشاء جدول (Creating a Table)

Original — CREATE TABLE

CREATE TABLE users (
    id INT UNSIGNED NOT NULL AUTO_INCREMENT KEY,
    name VARCHAR(128),
    email VARCHAR(128),
    password VARCHAR(128)
);

ALTER TABLE users ADD INDEX(email);

الترجمة: هذا الأمر ينشئ جدول users بأربعة حقول:

  • id — عدد صحيح موجب، ليس NULL، يزيد تلقائيًا، مفتاح أساسي.
  • name — نص بحد أقصى 128 حرفًا.
  • email — نص بحد أقصى 128 حرفًا.
  • password — نص بحد أقصى 128 حرفًا.

ثم يُضيف فهرسًا (INDEX) على حقل email لتسريع البحث:

ALTER TABLE users ADD INDEX(email);

مخرجات DESC users — تأكيد الهيكل:

5.4 الاتصال بقاعدة البيانات (Database Connection)

Database Connection

The PHP software connects to the database server by providing: Hostname (server), Database name, and User credentials (id/password).

$pdo = new PDO('mysql:host=localhost;port=8889;dbname=misc', 'fred', 'zap');

الترجمة: يتصل تطبيق PHP بقاعدة البيانات عبر توفير:

  • Hostname (server): اسم المضيف (localhost).
  • Database name: اسم قاعدة البيانات (misc).
  • Credentials: بيانات الاعتماد (اسم المستخدم fred وكلمة المرور zap).

5.5 أمثلة على استعلامات PDO

Example 1 — first.php: استعلام بسيط

first.php

<?php
$pdo = new PDO('mysql:host=localhost;port=8889;dbname=misc', 'fred', 'zap');

$stmt = $pdo->query('SELECT * FROM users');

while ( $row = $stmt->fetch(PDO::FETCH_ASSOC) ) {
    print_r($row);
}
?>

الناتج:

    [password] => 123

Example 2 — second.php: عرض النتائج في جدول HTML

second.php

<?php
$pdo = new PDO('mysql:host=localhost;port=8889;dbname=misc', 'fred', 'zap');

$stmt = $pdo->query('SELECT name, email, password FROM users');

echo '<table border="1">' . "\n";
while ( $row = $stmt->fetch(PDO::FETCH_ASSOC) ) {
    echo "<tr><td>";
    echo($row['name']);
    echo("</td><td>");
    echo($row['email']);
    echo("</td><td>");
    echo($row['password']);
    echo("</td></tr>\n");
}
echo "</table>\n";
?>

📌 ما يفعله هذا الملف:

  • ينشئ اتصالًا بقاعدة البيانات.
  • يُشغّل استعلامًا لجلب name, email, password من جدول users.
  • يطبع جدول HTML يحتوي على صفوف النتائج.

Example 3 — pdo.php و third.php: عزل الاتصال في ملف منفصل

Pattern — Put connection info in a single file

Put database connection information in a single file and include it in all your other files.

الترجمة: ضع معلومات الاتصال بقاعدة البيانات في ملف واحد، ثم ضُمّنه في جميع ملفاتك الأخرى.

pdo.php — ملف الاتصال

<?php
$pdo = new PDO('mysql:host=localhost;port=8889;dbname=misc', 'fred', 'zap');

// See the "errors" folder for details...
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
?>

third.php — استخدام الاتصال

<?php
require_once "pdo.php";

$stmt = $pdo->query("SELECT * FROM users");
while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
    print_r($row);
}
?>

📌 فوائد عزل الاتصال:

  • ✅ صيانة أسهل: تغيير بيانات الاتصال في مكان واحد فقط.
  • ✅ تقليل التكرار: لا حاجة لكتابة بيانات الاتصال في كل ملف.
  • ✅ الأمان: يمكن حماية الملف عبر صلاحيات نظام الملفات.
  • ✅ سهولة النقل: نقل التطبيق إلى خادم آخر يتطلب تغيير ملف واحد فقط.

7. تنظيم ملفات الموقع (Site Organization)

7.1 الحاجة لتنظيم ملفات الموقع (The Need to Organize Site Files)

Original

Thus far, we have placed all our site files into the main (root) website folder. As a website becomes larger and more sophisticated, a single folder becomes too cluttered to manage effectively. To better organize our site, we can group similar files, such as images and CSS files, into their own dedicated subfolders.

الترجمة: حتى الآن، كنا نضع جميع ملفات الموقع في المجلد الرئيسي (root). مع نمو الموقع وتعقده، يصبح المجلد الواحد مزدحمًا جدًا لإدارته بفعالية. لتنظيم الموقع بشكل أفضل، يمكننا تجميع الملفات المتشابهة (مثل الصور وملفات CSS) في مجلدات فرعية مخصصة.

بنية موقع منظمة

Website/
├── css/
│   └── mycss.css
├── images/
│   ├── flowers.jpg
│   ├── orange.jpg
│   └── pink.jpg
└── index.html

الترجمة: المجلد الرئيسي يحتوي على ملف HTML الرئيسي + مجلدات فرعية للصور والأنماط.

7.2 المسارات النسبية (Relative Paths)

Original

Once we move site files to subfolders, we need a way to tell the browser where to find them. To do this, we use relative paths.

الترجمة: بمجرد نقل ملفات الموقع إلى مجلدات فرعية، نحتاج إلى طريقة لإخبار المتصفح بمكان وجودها. للقيام بذلك، نستخدم المسارات النسبية (Relative Paths).

Example — Relative Path

<div class="gallery">
  <img src="images/flowers.jpg" />
  <img src="images/orange.jpg" />
  <img src="images/pink.jpg" />
</div>

ملاحظات:

  • المسار دائمًا نسبي إلى الملف الذي يقوم بالإشارة (في هذه الحالة index.html).
  • استخدم دائمًا الشرطة المائلة الأمامية (/) في مسارات الملفات، وليس الشرطة المائلة العكسية (\).

7.3 المسارات المطلقة (Absolute Paths)

Original

A common mistake committed by novice web designers is to copy and paste the full path to a local file in their markup. This can be a frustrating error, as the browser on our own computer can locate and display the image. But when the site is uploaded to a live web server, the image won't appear, since the location is no longer valid. These paths, since they are not relative to the current location, are known as absolute paths.

الترجمة: خطأ شائع يرتكبه مصممو الويب المبتدئون هو نسخ ولصق المسار الكامل لملف محلي في كودهم:

<img src="file:///C:/Users/me/Desktop/Website/images/pink.jpg" />

هذا خطأ محبط، لأن المتصفح على جهازك يمكنه تحديد موقع الصورة وعرضها. لكن عند رفع الموقع إلى خادم ويب حي، لن تظهر الصورة، لأن الموقع لم يعد صالحًا. هذه المسارات، لأنها ليست نسبية للموقع الحالي، تُسمى المسارات المطلقة (Absolute Paths).

⚠️ خطأ شائع: لا تستخدم مسارات مطلقة مثل file:///C:/... أو http://localhost/... داخل كود HTML — استخدم دائمًا مسارات نسبية.

7.4 ورقة الأنماط الخارجية في مجلد منفصل (External CSS in Subfolder)

Example

<head>
  ...
  <link rel="stylesheet" type="text/css" href="css/mycss.css" />
</head>

الترجمة: عندما ننقل ملف CSS إلى مجلد css/، نشير إليه في وسم <link> بالمسار css/mycss.css.

المسارات النسبية داخل ورقة الأنماط

Example — Background image in CSS

body {
    background-image: url('../images/orange.jpg');
}

الترجمة: عندما يكون ملف CSS في مجلد css/ ويحتاج إلى صورة في مجلد images/، نستخدم:

  • .. (نقطتان) = الصعود مجلدًا واحدًا.
  • / = الانتقال إلى مجلد آخر.
  • images/orange.jpg = المسار داخل المجلد الهدف.

📌 قاعدة مهمة:

المسار دائمًا نسبي إلى الملف الذي يقوم بالإشارة. في حالة CSS، الملف المُشير هو ملف CSS نفسه داخل مجلد css/، وليس index.html.

7.5 نمط MVC — تنظيم بنية المشروع (MVC Pattern)

Original

For larger projects, we organize files into three main folders: Controller (handles user requests), Model (handles database operations), View (handles display). Plus supporting folders: css, js, img, db.

الترجمة: للمشاريع الأكبر، نُنظّم الملفات في ثلاثة مجلدات رئيسية: Controller (يتعامل مع طلبات المستخدم)، Model (يتعامل مع عمليات قاعدة البيانات)، View (يتعامل مع العرض). بالإضافة إلى مجلدات دعم: css، js، img، db.

مجلد controller/ — المتحكم

يحتوي على الملفات التي تستقبل طلبات المستخدم وتنسقها بين Model و View.

أمثلة: loginController.php، productController.php...

مجلد model/ — النموذج

يحتوي على الملفات التي تتعامل مباشرة مع قاعدة البيانات — استعلامات PDO.

model/
├── Customers/
├── uploads/
├── Users/
├── customer.php
├── dashboard.php
├── deleteProduct.php
├── editProduct.php
├── footer.php
├── logout.php
├── navigation.php
├── product.php
├── product_cards.php
├── side_info.php
├── user.php
├── viewCustomer.php
├── viewProduct.php
└── viewUser.php

مجلد view/ — العرض

يحتوي على الملفات التي تعرض واجهة المستخدم (HTML + CSS).

view/
├── index.php
├── login.php
└── registration.php

📌 مثال حقيقي — Inventory Management:

موقع إدارة المخزون على http://localhost:8080/Inventory-Management/view/login.php — يستخدم بنية MVC كاملة مع فصل الملفات بحسب المسؤوليات.

7.6 ملاحظات على include و require

Original — Types of Includes

  • include — a warning is displayed and the script continues.
  • require — an error is displayed and the script stops.
  • include_once — same as include, but the file is only included once per page request.
  • require_once — same as require, but the file is only included once per page request.

الترجمة: أنواع تضمين الملفات:

الأمر عند الفشل التضمين المتكرر الاستخدام
include تحذير + استمرار مسموح تضمين ملفات صغيرة غير حرجة
require خطأ + توقف مسموح تضمين ملفات حرجة (مثل الاتصال بقاعدة البيانات)
include_once تحذير + استمرار ممنوع (مرة واحدة) دوال أو تعريفات
require_once خطأ + توقف ممنوع (مرة واحدة) ملفات الاتصال بقاعدة البيانات — الأكثر شيوعًا

📌 الأكثر استخدامًا في المشاريع:

require_once "pdo.php"; — لأنه يضمن تحميل ملف الاتصال مرة واحدة فقط، وإن فشل التحميل يتوقف التنفيذ فورًا (بدلًا من تنفيذ أوامر بدون اتصال).
